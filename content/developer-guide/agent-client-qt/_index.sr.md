`LibreAgent::ClientQt` је библиотека коју Qt или KDE апликација повезује да би
разговарала са картичним агентом. Деветнаест јавних заглавља стоји под
`client/qt/include/LibreSCRS/AgentClient/`, и то је једина група у јавној
површини LibreAgent-а ван простора имена `Agent::`.

Провера да ли је ова страница довољна: ко је прочитао само њу треба да уме да
покрене једну операцију и обради њен исход, а да не отвори изворни код
LibreAgent-а.

## Повезивање

```cmake
find_package(LibreAgent 5.0 CONFIG REQUIRED COMPONENTS ClientQt)

target_link_libraries(my_app PRIVATE LibreAgent::ClientQt)
```

Списак компоненти је важан: тражење пакета без њега тера га да испита сваку
компоненту коју нађе и за сваку покрене њен `find_dependency()`. За изградњу
саме библиотеке треба `-DLIBREAGENT_BUILD_CLIENT_QT=ON`, што је подразумевано
**искључено** — види
[Изградњу из изворног кода](/developer-guide/building-from-source/).

Ваша апликација повезује Qt6 и ову библиотеку. **Не** повезује LibreMiddleware,
и не треба јој PC/SC слој: свака картична радња дешава се у агенту.

## Три објекта

```
sharedAgentClient()  ──▶ AgentClient          веза + откривање
                              │
                              ├─▶ AgentReader   један читач
                              │        │
                              │        └─▶ AgentCard  једна убачена картица
                              │                 │
                              └─────────────────┴─▶ AgentOperation  један захтев
```

`AgentClient` држи превоз, прати да ли је агент доступан, и одржава регистре
читача и картица из агентовог снимка откривања плус живих обавештења о додавању
и уклањању. Превоз — D-Bus на Linux-у — унутрашњи је детаљ; ништа што је везано
за превоз не појављује се на овој површини.

Радије користите приступник за цео процес него сопствену конструкцију:

```cpp
#include <LibreSCRS/AgentClient/SharedAgentClient.h>

auto client = LibreSCRS::AgentClient::sharedAgentClient();
```

Сваки позивалац добија исти примерак, па процес успоставља једну везу уместо по
једну по потрошачу, а његово унутрашње праћење доступности држи стање живим —
дуготрајан дељени клијент *види* агента који се активира на захтев како се
појављује после хладног старта.

Једна ограда коју заглавље каже наглас: ово рачуна на то да у процесу постоји
тачно једна копија библиотеке, што подразумевана дељена изградња и даје.
Статичко умножавање преко граница додатака исковало би по једног „дељеног“
клијента по копији, а то је познат начин отказивања Qt статичког стања.

### Конструктор је посао већ обавио

```cpp
LibreSCRS::AgentClient::AgentClient client;
if (client.isAvailable()) {
    for (auto* reader : client.readers()) { /* ... */ }   // важи већ у овој линији
}
```

Конструкција изводи **ограничену** синхрону проверу доступности и, ако је агент
доступан, попуњава почетни регистар пре повратка. Ту се наоружавају и живе
претплате, па каснија појава или нестанак и промене регистра стижу као
`availabilityChanged`, `readersChanged` и `cardChanged`, без анкетирања.

`readers()` враћа читаче у **детерминистичком поретку по идентификатору**,
никада по редоследу обиласка хеша. Ако исцртавате списак, тај поредак је дељени
примитив који треба користити, да се две површине у истој апликацији не разиђу
око редоследа истих читача.

### Две врсте „нема агента“

```cpp
client.isAvailable();      // доступан управо сада
client.agentInstalled();   // инсталиран: доступан сада, или се покреће на захтев
```

Одговарају на различита питања, а празно стање пред корисником треба оба.
„Агент није инсталиран — ево како да га инсталирате“ и „ниједна картична радња
још није покренула агента“ траже различите речи и различита дугмад.
`agentInstalled()` је такође ограничена провера и никада не виси.

### Откривање способности

```cpp
if (client.hasFeature(QStringLiteral("batch-sign"))) { /* понуди */ }
```

`features()` је празан пре него што агент буде доступан, као и према агенту
старијем од те површине — то није грешка. `agentVersion()` је **само податак за
приказ**: прозор „О програму“, извештај за подршку. То је слободан низ који
агент бира; никада га немојте рашчлањивати да бисте одлучили шта агент уме. За
то служи `hasFeature()`.

## Покретање операције

Сваку картичну радњу кује метода на `AgentCard`-у (или
`AgentClient::certificateDer()`), она се одмах враћа, и никада није нулта:

```cpp
#include <LibreSCRS/AgentClient/AgentCard.h>
#include <LibreSCRS/AgentClient/AgentOperation.h>

using namespace LibreSCRS::AgentClient;

AgentCard* card = client->card(cardId);
if (!card) { return; }

AgentOperation* op = card->readIdentity();

QObject::connect(op, &AgentOperation::groupReady, this,
                 [](const FieldGroup& group) {
                     // прогресивна испорука: исцртавај како поља стижу
                 });

QObject::connect(op, &AgentOperation::finished, this, [op, this] {
    if (op->status() != OperationStatus::Ok) {
        showFailure(op);            // види „три осе грешака“ испод
        return;
    }
    render(op->identityResult());   // сређено пре него што је finished() опалио
});
```

Доступне операције:

| Позив | Над | Типизиран резултат |
|---|---|---|
| `readIdentity()` | `AgentCard` | `identityResult()` |
| `getPhoto()` | `AgentCard` | `takePhotos()` |
| `readCertificates()` | `AgentCard` | `certificatesResult()` |
| `readTokenInfo()` | `AgentCard` | метаподаци токена |
| `sign(certId, document, options)` | `AgentCard` | артефакт потписа |
| `signBatch(certId, docs, options)` | `AgentCard` | редови по документу |
| `listCredentials()` | `AgentCard` | `credentialsResult()` |
| `managePin(pinId, verb, options)` | `AgentCard` | исход над акредитивом |
| `activateSigningKey()` | `AgentCard` | исход над акредитивом |
| `certificateDer(readerId, certId)` | `AgentClient` | `certificateDerResult()` |

Свака операција је QObject-родитељски везана за објекат који ју је исковао, па
никада не надживи своју картицу или клијента. Обришите је раније ако сте
завршили са њом.

### Четири јемства на која се вреди ослонити

То су делови које је ручно најлакше погрешити, и разлог да се користи ова
библиотека уместо да сами говорите жицу.

1. **`finished()` опали тачно једном, икада** — и када је исход био познат већ у
   тренутку ковања. Позив који агент одбије на улазу, или операција која се
   завршила пре него што је објекат довршио конструкцију, свој завршетак
   *ставља у ред* петље догађаја уместо да га емитује из конструктора. Тако
   потрошач који се на `finished()` закачи тек у следећој линији, а раније није
   ни имао прилику, ипак га види.
2. **Све је сређено пре него што `finished()` опали.** `status()`,
   `errorCode()`, `callError()` и типизиран приступник резултата важе унутар
   директно повезаног слота, читани синхроно, без додатне синхронизације.
3. **Сигнали стижу на нити на којој живи објекат који је исковао операцију.**
   Никада са туђе нити, па директна веза на тој нити не може да се трка са
   стањем.
4. **Изгубљен резултат је гласан.** Тамо где агент задржава садржај, изгубљен
   или претекнут једнократни сигнал резултата опоравља се из њега. Тамо где се
   не може опоравити, операција износи комуникациону грешку уместо да се
   представи као тих празан успех.

Последње је најдрагоценије и најмање видљиво: ручно писан клијент који пропусти
једнократни сигнал резултата пријави успех без података, а квар изгледа као
картица која није вратила ништа.

### Саглашеност унапред

`OperationStatus` и `OperationPhase` замрзнути су на жици и расту само
додавањем, а клијент је грађен да преживи новијег агента:

- непрепознат завршни **статус** третира се као грешка, а не износи као
  безимена вредност набрајања;
- непрепозната **фаза** оставља последњу познату добру фазу на месту —
  `progress()` и даље напредује на таквој пријави, само се фаза не враћа на
  нешто бесмислено;
- непрепознат бројчани `ErrorCode` пролази дословно.

### Отказивање

```cpp
op->cancel();   // испали и заборави
```

Завршни исход и даље стиже кроз `finished()`, обично са отказаним статусом.
Никада се не испоручује синхроно из `cancel()`-а.

## Три осе грешака

Овај део вреди прочитати двапут. Неуспела операција јавља на до три ортогоналне
осе, и коришћење само једне губи податак који ће вам затребати.

```cpp
op->errorCode();   // ErrorCode                 — агент је одговорио, неуспехом
op->callError();   // CallError                 — одговор са жице никада није ни стигао
op->syncError();   // std::optional<SyncError>  — које именовано одбијање је било
```

**`errorCode()` и `callError()` међусобно се искључују.** Када је агент
одговорио — макар и неуспехом — одговор је `ErrorCode`, а `callError()` остаје
`None`. Када клијент дотле није ни стигао, `errorCode()` остаје `None` а разлог
је `CallError`:

```cpp
enum class CallError : std::uint8_t {
    None, AgentUnavailable, Timeout, AccessDenied,
    InvalidArguments, TransportFailure, ProtocolError,
};
```

`CallError` је **локалан**: он се сам никада не носи на жици.
`AgentUnavailable` значи да ниједан агент није доступан — а то је кориснику
сасвим друга порука него картица која је одбила PIN.

**Трећа** оса је сопствено име одбијања, и постоји зато што се више различитих
имена слива у једну корпу оне друге две. `UnknownCredential` и `InvalidRequest`
обоје пријављују `CallError::InvalidArguments`, а клијент чији се опоравак међу
њима разликује — поново излистај застареле идентификаторе, или прикажи трајан
неуспех — из корпе их не може разликовати. Име никада не мења оно што друге две
осе пријављују; оно каже које је од више имена из њихове корпе ово заправо било.

`syncError()` није заузет када ниједно име из тог речника није било у игри.
Разликовање иде по томе *ко је именовао*, а не по томе шта је пошло наопако:
локални квар при уоквиривању пријављује се на друге две осе, а читање имена
тамо приписало би га картици, што је други квар са другим опоравком.

Једно упозорење из заглавља вреди пренети: заузет
`SyncError::CommunicationError` **не** доказује да је та страна тако именовала
грешку. `sync-error` је речник текстуалних токена без места да непрепознат
токен пренесе даље, па име из новијег агента при декодирању деградира у ту
вредност на оба превоза. Читајте га као „именовано, али некорисно“ — никада као
позитивну идентификацију.

За поруку кориснику, `messageKey()` носи агентов сопствени i18n кључ завршног
исхода. Празан је на опорављеном завршетку, где уместо тога пресликавате
`errorCode()`.

## Истек времена је ваша обавеза

```cpp
inline constexpr int kHandshakeTimeoutMs   = 1000;   // јефтине синхроне размене
// ... kDefaultCallTimeoutMs, kLongOperationTimeoutMs
```

Обичан `int` у милисекундама, јер сваки Qt тајмер и сокет API који их прима
узима `int` msec.

Правило спровођења није уједначено, а претпоставка да јесте коштаће вас
заглављивања. Превози буџете за руковање и подразумевани позив примењују
интерно, на своје синхроне размене. `kLongOperationTimeoutMs` је **саветодавни
буџет који спроводи позивалац**: библиотека нема унутрашњег стражара и никада
сама не обара заглављену операцију. Клијент који хоће откривање застоја пушта
сопствени тајмер према тој константи и зове `cancel()` кад истекне.

Ништа на жици не носи истек времена. Агентов сопствени стражар по операцији
засебан је буџет на страни сервера, који клијент само посматра.

## Два дељена читача, и зашто су овде

Два заглавља у овој библиотеци постоје да спрече да се исти код напише на три
неспојива начина.

### `SecurityChecks.h`

Картични додатак оно што је проверио пријављује као обична идентитетска поља, а
вредност поља намерно је отворен низ — па ниједан затворен речник не описује
*облик* који та поља међусобно граде. Препуштен сваком потрошачу, тај облик се
изнова измишља по потрошачу: три међусобно неспојива читања исте групе била су
жива у овом пројекту истовремено, и **свако од њих је имало тест који пролази**,
јер је сваки тест мерио читача према представи о жици коју је имао његов аутор.

Тај облик се уместо тога држи овде. Оба десктоп клијента граде ову библиотеку,
па је провера издвојена овде издвојена на исти начин у свима њима.

Шта намерно *не* ради: не преводи и не суди. `status`, `category` и `reason`
враћају се као сопствени токени произвођача, а `SecurityCheckEntry::reason` је
**кључ**, а не реченица. Претварање токена у речи тражи каталог на језику
читаоца, а ти живе у GUI домаћинима.

### `SealedPayload.h`

Једини ревидиран читач за мале, потпуно баферисане садржаје које агент предаје
као дескрипторе фајлова. Свако место које такав дескриптор претвара у бајтове
иде кроз `readBoundedPayload()` уместо да по месту позива изнова пише stat и
read, па се ограничење бајтова и провере облика дескриптора не могу применити на
једном месту а заборавити на другом.

Његова таваница од 8 MiB поштена је о томе шта јесте: **нова** инваријанта коју
тај читач уводи, а не понављање границе која се спроводи негде узводно. Агент
сирове бајтове поља са фотографијом гура у дескриптор без сопствене провере
дужине, а таваница оквира од 1 MiB на сокет жици ограничава CBOR тело, не
дескриптор поред њега.
