Дванаест јавних LibreMiddleware заглавља чини површину поверења и сертификата:
`Trust/` (4), `Certificate/` (3), `Secure/` (2) и `SecureChannel/` (3).

Две од ових група вреди прочитати пре него што напишете било шта ново, из
супротних разлога. `Secure::String` и `Secure::Buffer` су типови које треба
поново користити уместо измишљати; `Trust::CscaMasterList` је површина чија су
**подразумевана понашања** суштина, а позивалац их споља не може проверити.

## Тајне које се бришу: `Secure::String` и `Secure::Buffer`

Оба нулирају своју меморију при уништавању и при премештању из њих, кроз куку
алокатора који брише плус изричит пролаз преко бајтова оптимизованих за кратке
низове, који до алокатора никада не стигну. Ниједан није контејнер опште намене.

Разликују се у тачно једном погледу, намерно:

| | `Secure::String` | `Secure::Buffer` |
|---|---|---|
| Копирање | **може се копирати**, свака копија се брише засебно | **само премештање**, копија обрисана |
| За | тајне које човек куца — PIN-ови, лозинке, токени | изведене или бинарне тајне — бајтови кључева, APDU одговори, међурезултати потписивања |

Та асиметрија је намерна, није раскорак. Текстуална тајна обично хоће да седи у
`std::optional`-у или у структури подешавања и да путује кроз аргументе
функција, па би забрана копирања коштала више него што доноси. Бинарна тајна
природније пролази кроз једног власника преко `std::move`-а, а тамо брисање
копије спречава случајан дупликат материјала кључа.

Оба су **thread-compatible**: различити примерци могу се користити паралелно без
спољне синхронизације, један примерак не може. Власништво између нити преносите
премештањем; приступ само за читање делите преко независних копија, никада преко
референци на један дељени примерак.

Пројектно правило је да се посегне за овим типовима пре него што се измисли
било шта — нов тип мора бити функционално различит *и* употребљен бар двапут да
би уопште постојао.

## Читање сертификата

`Certificate::ParsedCertificate` је поглед само за читање над DER кодираним
X.509 сертификатом. Његова фабрика може да омане, и прати
[обавезу `std::expected`](/developer-guide/sdk-reference/expected-result-handling/):

```cpp
#include <LibreSCRS/Certificate/ParsedCertificate.h>

auto parsed = LibreSCRS::Certificate::ParsedCertificate::fromDer(der);
if (!parsed) {
    show(parsed.error().userMessage);     // ParseError, никада празан
    return;
}

const auto subject = parsed->subject();               // DistinguishedName
const auto notAfter = parsed->notAfter();             // system_clock::time_point
const auto usage   = parsed->keyUsage();              // optional<vector<KeyUsageBit>>
const auto sans    = parsed->subjectAlternativeNames();
```

Приступници покривају оно што прегледачу сертификата или провери политике треба:
субјекат и издавалац, серијски број, верзија, прозор важења, алгоритам потписа
(као `ObjectIdentifier` и као опис), подаци о јавном кључу, употреба кључа и
проширена употреба кључа, алтернативна имена субјекта и издаваоца, и основна
ограничења. Приступници који враћају `optional` празни су када проширење не
постоји — а то је друга тврдња од празног списка, и разлика је важна нарочито
за употребу кључа.

`Certificate::DistinguishedName` и `Certificate::ObjectIdentifier` су два
вредносна типа која ти приступници враћају.

## `TrustStore` и `TrustStoreService`

`TrustStore` је сложено складиште сидара према коме мотор потписивања проверава
ланце:

```cpp
[[nodiscard]] ChainStatus validateChain(std::span<const CertificateView> chain) const;  // лист први
[[nodiscard]] std::optional<TrustAnchor> findIssuerOf(CertificateView certDer) const;
[[nodiscard]] std::vector<TrustAnchor> enumerableAnchors() const;
```

`TrustAnchor` носи DER бајтове плус **ознаку порекла** читљиву човеку, па
површина може да каже одакле је сидро дошло уместо да прикаже неприписан
сертификат.

`TrustStoreService` држи животни циклус. То је асинхрона фабрика која не баца, а
која је у 4.0 заменила обрисан наслеђени менаџер:

```cpp
auto service = LibreSCRS::Trust::TrustStoreService::create(trustConfig);
if (!service) { /* CreateError, са својим Kind и userMessage */ }

std::shared_ptr<const TrustStore> store = (*service)->trustStore();
```

Потрошачи — сервис потписивања, регистар додатака, домаћини — примају
`shared_ptr<TrustStoreService>` чистом конструкторском ињекцијом.

Поред складишта, износи и оно што кориснички интерфејс треба да би поштено
говорио о непотпуном материјалу поверења: `SourceStatus` по извору,
`AggregateStatus`, `sourceStatuses()` који именује сваки извор, посматрача
завршетка довлачења, и `waitForEagerFetches(deadline, token)` за позиваоца који
хоће да блокира на довлачењима при покретању, уз рок и токен отказивања.

### Ревносне наспрам лењих поузданих листа

```cpp
struct TrustedListSource {
    std::string url;
    bool lotl  = false;   // овај извор је Листа поузданих листа
    bool eager = false;   // довуци при подешавању, а не при потписивању
};
```

`eager` је подразумевано **false**, а то је одлука а не пропуст: домаћин без
мреже, или потрошач који никада не тражи ниво потписа коме треба сидро из
поуздане листе, није натеран на HTTPS размену при покретању. Инсталација која
би радије да падне гласно при покретању укључује га по извору.

Приметите шта `lotl` значи по цени. Листа поузданих листа показује на даље
листе, па лењи LOTL извор чини да *први* потпис коме затреба довуче LOTL плус
листе које он именује.

## Увоз ICAO CSCA мастер листе

`Trust/CscaMasterList.h` је три функције и ниједно стање, и то је најновија
површина овде. Објављена је уместо да се препусти позиваоцима зато што би
домаћин који би себи направио своју уз то добио OpenSSL зависност, CMS
верификатор и градитеља путања — и морао би поново да открије два подразумевана
понашања провере и једну заставицу градње путање које одлучују да ли се
исправни документи прихватају.

Заглавље не декларише **ниједан OpenSSL тип**, и не сме: сидра, сертификати и
отисци границу прелазе као бајтови, па потрошач који укључи заглавље поверења не
наслеђује уграђене OpenSSL декларације у сопствене преводилачке јединице.

```cpp
std::expected<VerifiedMasterList, MasterListError>
parseAndVerifyMasterList(const std::vector<std::uint8_t>& der,
                         const std::array<std::uint8_t, kSpkiSha256Size>* expectedSpkiSha256);

std::optional<std::array<std::uint8_t, kSpkiSha256Size>>
spkiSha256FromCertificateDer(/* сертификат издаваоца */);

bool signerChainsToAnyAnchor(const std::vector<std::uint8_t>& signerCertDer,
                             const std::vector<std::vector<std::uint8_t>>& anchorsDer);
```

### Шта провера ради, редом

1. Бајтови се декодирају као један CMS `ContentInfo`, иначе је одговор
   `NotAMasterList`.
2. **Сваки** `SignerInfo` проверава се над садржајем који објекат носи.
3. Ако је дат отисак, отисак SubjectPublicKeyInfo *неког* потписника мора му
   бити једнак.
4. Сидра се читају, а неуспех тамо стиже до позиваоца непромењен.

Четири ствари у том редоследу су носиве, и ниједна се не види из потписа.

**„Потписник“ значи сертификат који је проверио неки `SignerInfo`** — никада
онај који објекат само носи. CMS врећа сертификата није аутентификована, па
непознат може да подметне сертификат поузданог издаваоца поред своје листе а да
не дира ниједан потпис. Утврђена тврдња гласи „закуцан кључ је ово потписао“, а
не „закуцан сертификат путује уз ово“.

**Корак 4 је препрека, не формалност.** Под потписом стоји само потписани
атрибут `contentType`; поље `eContentType` поред њега није. Објекат који је
заиста потписао управо закуцан потписник, над правим бајтовима мастер листе,
под неким другим типом садржаја па накнадно преимењен, пролази кораке 2 и 3
голим. Поређење та два места једино је што га зауставља.

**Кораци 2 и 3 су у том редоследу намерно.** Поређење отиска прво одговорило би
на питање „да ли се овај отисак поклапа“ за листу чији потпис не важи — питање
без безбедносног садржаја, јер свако сме да копира сертификат у објекат који
није потписао. Зато се листа која и падне на потпису и именује неочекиваног
потписника пријављује као `BadSignature`.

**Ланац се не гради.** Сертификат потписника не везује се ни за шта, и не
проверава се на истек, употребу кључа, проширену употребу кључа, основна
ограничења ни повлачење. Идентитет почива искључиво на закуцаном отиску, који је
позивалац добавио неким другим путем. То није пропуст: мастер листа је оно што
*доноси* сидра, па при првом увозу нема за шта да се веже, а кад идентитет
почива на закуцаном кључу, сертификат око њега је контејнер а не акредитив. Две
од тих провера одбијале би сасвим исправне листе — истек, јер мастер листа
годинама надживи кључ који ју је потписао; проширена употреба кључа, јер CMS
подразумевано тражи `emailProtection`, па таква провера окреће леђа управо
исправно ICAO-профилисаном сертификату.

Функција не памти ништа између позива. Чување закуцаних вредности кроз увозе је
на позиваоцу.

### Закуцава се кључ, не сертификат

`spkiSha256FromCertificateDer()` је **једини подржан начин** да се произведе
вредност коју верификатор пореди, а постоје два очигледна начина да се погреши.
То није хеш сертификата: издавалац обнавља сертификат а задржава кључ, па би
свака обнова мењала закуцану вредност.

### Праћење законите ротације

`signerChainsToAnyAnchor()` је одлука коју верификатор намерно не доноси:
прихвати новог издаваоца ако се везује за сидро које је носила листа којој се
већ веровало.

**Ланац сме да заврши на било ком сидру, самопотписаном или не**, и то је носиво
а не уредно. CSCA **веза-сертификат** носи исти субјекат и исти јавни кључ као
нов самопотписан корен државе, али је потписан *одлазећим* кључем — дакле није
самопотписан, а ICAO мастер листе носе веза-сертификате поред самопотписаних.
Градитељ путање који би инсистирао на самопотписаном крају одговорио би `false`
о потписнику кога је та власт заиста издала, кад год је веза-сертификат једино
сидро које за њу држимо, или тек оно прво достигнуто међу сидрима са истим
субјектом.

**Тај одговор не садржи никакву тврдњу о времену**, ни на једном крају. Истекао
потписник се везује, као и истекло — или још неважеће — сидро. Кључ потписника
живи месецима док оно што је потписао живи годинама, па је истекао потписник
обичан случај а не сумњив. Позивалац коме треба провера датума мора да је уради
и не сме да је учита у овај одговор.

Шта *јесте* спроведено, да се ово не чита као „нема провера“: сваки потпис у
ланцу, основна ограничења која спречавају да лист усред ланца глуми CA, и
употреба кључа која издаваоцу дозвољава да потписује сертификате. Повлачење се
не консултује.

Једно питање, а три ситуације деле један одговор: „ниједно сидро није подешено“,
„ниједно се није декодирало“ и „не везује се“ све су `false`. Позивалац који
мора да их разликује зна сопствену конфигурацију и може то да каже.

### Увоз, у пракси

```cpp
using namespace LibreSCRS::Trust;

// Први увоз: прихвати било ког потписника, и запиши ко је био.
auto first = parseAndVerifyMasterList(bytes, nullptr);
if (!first) { return refuse(first.error()); }

store.remember(first->signerSpkiSha256, first->anchors);   // складиште позиваоца

// Каснија листа истог издаваоца: закуцај записан кључ.
auto next = parseAndVerifyMasterList(newBytes, &recordedFingerprint);
if (!next) {
    if (next.error() == MasterListError::SignerMismatch) {
        // Кључ се променио. Законита ротација, или напад — одавде изгледају
        // истоветно, па питамо да ли нов потписник потиче од онога што држимо.
        if (signerChainsToAnyAnchor(newSignerCertDer, heldAnchors)) {
            // прати ротацију и запиши нов отисак
        }
    }
    return refuse(next.error());
}
```

Свака враћена грешка је одбијање: случаја „не зна се“ нема. Позив или даје
сидра или именује прву проверу која је пала, а одбијања су тиха — грешка је цела
дијагноза, и ништа се не уписује у лог.

## Параметри безбедног канала

`SecureChannel/PaceParams.h` и `BacParams.h` носе параметре за два протокола
успостављања канала са е-пасошем. `ChannelErrors.h` носи стање животног циклуса
и таксономију грешака активације:

```cpp
enum class ChannelState : std::uint8_t { Open, Closed, Failed };
enum class ChannelActivationError : std::uint8_t {
    None, SelectAppletFailed, WrongSecret, ProtocolFailure,
    PacePinBlocked, PaceUnsupported, /* ... */
};
```

`Failed` значи да је канал поништен — статусном речи која говори о квару
безбедног преноса, или неуспехом провере MAC-а — и позивалац треба да га
одбаци и поново активира, а не да на њему понавља.

Две од тих вредности изгубиле су префикс `Pace` у 4.x линији, јер их и BAC пут
враћа: `WrongSecret` и `ProtocolFailure`. `PacePinBlocked` и `PaceUnsupported`
задржавају свој, јер их BAC никада не враћа.
[API политика](/developer-guide/sdk-reference/api-policy/) бележи зашто је то
преименовање било исправка на лицу места а не циклус застаревања.

Већина потрошача ове типове никада не дира директно: они предају захтев
`CardSession`-у, који држи животни век канала. Види
[Безбедне канале](/developer-guide/secure-channels/) и
[CardSession API за безбедни пренос](/developer-guide/card-session-sm/).
