Свако LibreSCRS издање потписано је двапут: **git таг** OpenPGP кључем, а
сваки **артефакт издања** cosign-ом у режиму без кључа. Та два потписа
одговарају на различита питања — таг доказује који је комит одржавалац издао,
а потпис артефакта доказује који је радни ток изградње направио фајл који сте
преузели — па пажљива провера ради обоје.

Исте податке носи и `KEYS` фајл у корену сваког LibreSCRS спремишта. Ова
страница постоји да би `SECURITY.md` или README могли да је линкују и да
команде испод стоје на једном месту када се промене.

## Провера тага издања

```
gpg --import KEYS
git verify-tag <TAG>
```

Пројектни кључ за потписивање издања, важи од 4.0 надаље:

```
pub   ed25519 2026-04-27 [C] [expires: 2031-04-26]
      6B05889AC9A6A7188DF639B06F27A989C2031D16
uid           [ultimate] LibreSCRS Release Signing <librescrs@proton.me>
sub   ed25519 2026-04-27 [S] [expires: 2028-04-26]
      D95BE325E2EC2E90E1DC750422941CECE07A5167
```

Први отисак је **примарни** кључ, а други је потписни подкључ — и управо
подкључ се појављује у потпису тага. Када читате излаз
`gpg --verify --status-fd=1` уместо облика намењеног човеку, *прво* поље реда
`VALIDSIG` је потписни подкључ а *последње* је примарни кључ; упоредите оно
право.

## Провера артефакта издања

Артефакти издања носе cosign пакет `<artifact>.sigstore.json`. Потпуна
команда је:

```
cosign verify-blob <artifact> \
  --bundle <artifact>.sigstore.json \
  --certificate-identity-regexp 'https://github\.com/LibreSCRS/.*\.github/workflows/release\.yml@refs/tags/.*' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com'
```

### Зашто две `--certificate-*` заставице нису опционе

`cosign verify-blob --bundle <bundle> <artifact>` сам за себе доказује само да
артефакт одговара пакету који је уз њега стигао. О томе **ко** је направио
једно или друго не говори ништа. У режиму без кључа не постоји дуготрајан
јавни кључ који бисте препознали; идентитет живи у краткотрајном сертификату,
а те две заставице су оно што га закључава:

- `--certificate-identity-regexp` захтева да потпис долази из радног тока
  издања у GitHub организацији `LibreSCRS`, покренутог над тагом;
- `--certificate-oidc-issuer` захтева да је тај идентитет потврдио GitHub-ов
  OIDC издавалац, а не неки други издавалац идентитета који такође уме да
  изда Sigstore сертификат.

Без њих нападач који замени и артефакт и пакет пролази проверу. Са њима би
морао још и да потпише као LibreSCRS-ов радни ток издања.

## Пријава безбедносног пропуста

Свако спремиште носи `SECURITY.md` са тренутном адресом за пријаву и табелом
подржаних верзија за ту компоненту.
