Од 5.0 са вашом картицом заправо разговара **LibreSCRS картични агент**.
LibreCelik, LibreKDE, Firefox, Thunderbird и `ssh` сви су његови клијенти. Ако
агент није инсталиран, те апликације се нормално покрену па не нађу картицу —
зато се он инсталира први, пре свих њих.

Имена пакета и редослед инсталације су на
[страници за преузимање](/downloads/).

## Зашто уопште агент

Смарт картица је уређај са једном сесијом. Пре 5.0 је свака апликација која је
хтела вашу картицу сама отварала сесију: GUI, прегледач кроз PKCS#11 и алат за
потписивање држали су по своју, свако је засебно тражио ваш PIN, а побеђивао је
онај који први стигне до читача. Други је добијао неразумљив неуспех.

Један посредник држи картицу и њене тајне, а све остало је његов танак клијент.
То је један одговор на три засебна проблема: нема више трке за читачем, постоји
једно место које зна да ли је ваш PIN већ проверен, и — пошто агент акредитиве
прикупља кроз засебан процес-упитник — ваш PIN никада не улази у адресни
простор прегледача који је тражио потпис.

Исти облик описан је са програмерске стране под
[Архитектуром](/developer-guide/architecture/).

## Провера да ради

Агент је systemd сервис по кориснику, на сесијској магистрали:

```
systemctl --user status librescrs-agent.service
```

Активира се **на захтев**: не ради док прва картична радња то не затражи, па је
`inactive (dead)` одмах после инсталације нормално стање, а не квар. Убаците
картицу, отворите LibreCelik и проверите поново.

Да потврдите да је заузео име на магистрали:

```
busctl --user list | grep org.librescrs.Agent
```

## Покретање на сваком пријављивању

Агент намерно **није** укључен на пријављивање подразумевано: на машини где
картицу користите двапут месечно, сервис који креће са сваком сесијом није оно
што желите. Ако је користите свакодневно, укључите га:

```
systemctl --user enable --now librescrs-agent.service
```

Повратак на активацију по потреби:

```
systemctl --user disable --now librescrs-agent.service
```

## Упит за ауторизацију

Захтеви клијената пролазе кроз **polkit**, па ћете видети системски дијалог за
ауторизацију први пут кад нека апликација затражи од агента нешто из дате класе
радњи. Класе су намерно раздвојене, и не траже све исто:

| Радња | Подразумевано |
|---|---|
| Потписивање картицом | дозвољено активној сесији — PIN је капија сагласности |
| Коришћење картице из PKCS#11 апликације | дозвољено активној сесији — из истог разлога |
| Управљање акредитивима картице (промена PIN-а, деблокада) | дозвољено активној сесији |
| Измена подешавања потписивања | дозвољено активној сесији |
| Измена подешавања поверења и временског жига | **тражи потврду идентитета**, у свакој сесији |

Последњи ред вреди прочитати двапут. Подешавања поверења одлучују према којим
се сертификатима потпис проверава, па је њихова измена корак подизања поверења
и тако се и третира; само потписивање чува PIN који ћете управо укуцати, па би
други дијалог испред њега само научио човека да прокликта кроз оба.

Упит се јавља **једном по класи радњи по сесији**, не по операцији. Ако га
видите пред сваки потпис, нешто рестартује агента између њих.

## Упити за PIN, CAN и MRZ

PIN-ове, CAN-ове и MRZ-ове никада не прикупља апликација коју користите. Тражи
их засебан процес-упитник (`librescrs-pinentry-kde`) и предаје их агенту преко
приватног интерфејса на сесијској магистрали. То је засебан пакет, и без њега
ниједна PIN операција није могућа — ако сте инсталирали агента а унос PIN-а не
ради ништа, тај пакет недостаје.

## Прегледачи, SSH и остали PKCS#11 клијенти

Агент инсталира PKCS#11 модул који те апликације откривају кроз p11-kit.
Подешавање прегледача и уклањање ручно направљене регистрације старијег
директног модула стоје у [водичу за PKCS#11](/sr/user-guide/pkcs11/).
