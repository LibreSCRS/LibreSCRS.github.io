Свака PKCS#11 апликација — Firefox, Chrome, Thunderbird, `ssh`, Kleopatra —
може да користи вашу смарт картицу кроз LibreSCRS, и док је LibreCelik затворен.

Од 5.0 је модул који те апликације учитавају **клијентски модул картичног
агента**, `librescrs-pkcs11-agent.so`. Он сам не ради никакву криптографију и
не држи ниједну тајну картице: пресликава PKCS#11 `C_*` позиве на агента по
кориснику, који држи картицу, упитник и политику ауторизације.

Практичну последицу вреди рећи пре свега осталог. Токен објављује **заштићен
пут за потврду идентитета**, па се ваш PIN куца у агентов сопствени упитник и
никада не стиже до апликације. Апликацији која PIN проследи у `C_Login` он се
игнорише.

**Типови картица који се препознају аутоматски:**

- **CardEdge** — српска лична карта Gemalto (2014+), IF2020 за странце, ПКС
  Привредна комора
- **PKCS#15** — свака картица саглашена са PKCS#15
- **PIV** — америчке федералне идентификационе картице (NIST SP 800-73)

## Инсталација

Нема шта да се преузима. Модул инсталира пакет картичног агента — види
[Инсталацију картичног агента](/sr/user-guide/install-agent/) и
[страницу за преузимање](/sr/downloads/) — и тај исти пакет га региструје код
p11-kit-а. Апликације повезане са p11-kit-ом налазе га без икаквог подешавања
по апликацији.

Потврда регистрације:

```
p11-kit list-modules
```

LibreSCRS унос мора бити на списку, а његов токен мора приказати
`protected authentication path`. То је ред који је важан: без њега би
апликација покушала сама да прикупи PIN.

Иста команда исписује и апсолутну путању модула, коју одељци испод зову
`<module>`. На уобичајеној Linux инсталацији то је
`/usr/lib/pkcs11/librescrs-pkcs11-agent.so`.

## Ако сте PKCS#11 модул инсталирали пре 5.0

До 4.x је middleware испоручивао сопствени директан модул и упућивао вас да га
ручно региструјете. Тај модул више није регистровани добављач, а једна картица
која нуди два добављача са два различита модела уноса PIN-а управо је стање
које ово издање укида. Три популације, а менаџер пакета чисти само једну:

- **Инсталирали сте дистрибуцијски пакет.** Нема шта да се ради. `pacman`,
  `dpkg` и `rpm` уклањају фајлове који испадну из манифеста.
- **Инсталирали сте из изворног кода са `cmake --install`.** Не чисти се:
  `install()` преписује, никада не брише. Уклоните стару библиотеку и сваку
  регистрацију коју сте ручно додали.
- **Инсталирали сте из архива издања**, по упутству које је то издање
  испоручило. Ни то се не чисти, а управо та инсталациона база стварно постоји,
  јер ју је објављени архив и направио. Уклоните регистрацију:

  ```
  rm ~/.config/pkcs11/modules/librescrs.module
  ```

Затим поново покрените `p11-kit list-modules` и потврдите да је на списку тачно
један LibreSCRS добављач. Ако прегледач и даље нуди два уређаја за једну
картицу, остала је и регистрација у NSS бази — види
[Firefox и Thunderbird](#firefox-и-thunderbird) испод и уклоните унос који сте
додали.

## Firefox и Thunderbird

Firefox и Thunderbird на већини Linux дистрибуција користе p11-kit и не траже
никакво подешавање. Ако ваш не:

1. **Подешавања** → **Приватност и безбедност** → **Безбедност** →
   **Безбедносни уређаји**
2. **Учитај**
3. Назовите га `LibreSCRS` и дајте путању модула из `p11-kit list-modules`
4. **У реду**

Убаците картицу и освежите. Када сервис затражи клијентски сертификат — на
пример еУправа — PIN тражи агентов упитник.

Застарео унос уклањате у истом дијалогу, опцијом **Уклони**.

## Chrome и Chromium

Chrome на Linux-у користи NSS базу, не p11-kit. Регистрација, једном:

```
# modutil, ако већ није присутан
sudo apt install libnss3-tools     # Debian/Ubuntu
sudo dnf install nss-tools         # Fedora

modutil -dbdir sql:$HOME/.pki/nssdb -add librescrs -libfile <module>
```

Рестартујте Chrome. Сертификати картице појављују се под **Подешавања** →
**Приватност и безбедност** → **Управљање сертификатима**.

## OpenSSH

Испис јавних кључева са картице:

```
ssh-keygen -D <module>
```

Пријава помоћу њега:

```
ssh -I <module> user@host
```

Или, у `~/.ssh/config`:

```
Host myserver
    PKCS11Provider <module>
```

## Провера из командне линије

```
pkcs11-tool --module <module> -T
```

Токен мора да наведе `protected authentication path`. Избор преко PKCS#11 URI-ја
(`pkcs11:token=…`) ради кроз све p11-kit модуле чим агент ради.

## Изолација ван процеса

Подразумевано модул ради у процесу апликације која га зове, где не држи ниједну
тајну и не ради криптографију. Ако вам ни то не одговара, p11-kit може да га
угости ван процеса — било као краткотрајно дете по потрошачу, било као
дуготрајан сервер по кориснику преко сокета. Оба су само измене у инсталираном
`.module` фајлу, који оба облика документује на лицу места; сама библиотека је
иста у оба случаја.

## macOS

**На macOS-у у 5.0.0 нема агентског PKCS#11 добављача.** macOS домаћин агента
је написан и покренут на стварном хардверу, али није део овог издања, а није ни
посреднички модул за њега.

Корисник macOS-а коме данас треба PKCS#11 добављач гради директан модул
middleware-а из изворног кода и региструје га изричито. То је исти модул који
је Linux користио до 4.x, са истим својством против кога ова страница иначе
говори: PIN прикупља апликација.

## Linux домаћини без интерфејса

Машина која не покреће агента — рецимо сервер за изградњу који потписује
артефакте — и даље може да користи директан модул middleware-а. Гради се и
инсталира као и раније; нестала је само његова p11-kit декларација, а
`-DLIBREMIDDLEWARE_INSTALL_P11KIT_MODULE=ON` је враћа:

```
cmake -S /path/to/LibreMiddleware -B build \
      -DLIBREMIDDLEWARE_INSTALL_P11KIT_MODULE=ON
cmake --build build --target librescrs-pkcs11
```

На таквом домаћину нема упитника, па PIN даје апликација — и зато је ово случај
без интерфејса, а не подразумевани.
